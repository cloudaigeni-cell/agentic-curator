agentic-curator · field guide

One orchestrator, six specialists, one protocol boundary

A working multi-agent system you can turn over in your hands. Drag the model to rotate it, pull the layers apart, then step through a real run and watch which parts lift. Every block maps to one Python file in the repository.

orchestration subagents may remove files policy gate shared services MCP your files

Five locks between an agent and your files

None of them depends on a model behaving well. Each is a few lines of ordinary code you can read and test.

LOCK 1 · policy.py

Dry run unless you say otherwise

Without --execute the policy refuses every change. The demo's first run only writes a plan.

LOCK 2 · messages.py

Finders cannot act

Agents emit proposals with evidence: a matching hash, a similarity score. Only the deletion agent may act, and it proposes nothing.

LOCK 3 · policy.py

The token is the plan

Approval is a hash of the exact targets. Add one path after review and the token no longer matches, so the whole batch is refused.

LOCK 4 · library_server.py

No delete tool exists

The server offers move_to_trash and nothing stronger. A manifest records each original path; curator restore undoes it.

LOCK 5 · library_server.py

A real sandbox

Every path is resolved against the library root. ../../etc/passwd is rejected by the server, whatever a document tells an agent to do.

Start here

In WSL (Ubuntu)

# one-time
sudo apt update && sudo apt install -y python3-venv git
git clone https://github.com/cloudaigeni-cell/agentic-curator
cd agentic-curator
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

# check, then run on planted sample data
curator doctor
curator demo            # plan only
curator demo --execute  # moves 8 files to trash
curator restore --library demo_library
